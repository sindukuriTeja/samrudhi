## 2. Part I — Enterprise operating model

### 2. Design principle: "Agents as accountable digital resources"
Three classifications of agents, plus a fourth independent supervisory category:
- **Executive Superagents** — "Enterprise strategy, planning, prioritisation, delegation and performance oversight"
- **Functional Agents** — "Own specific business functions and their measurable outcomes"
- **Execution Subagents** — "Perform bounded tasks such as research, writing, checking, scheduling and reporting"
- **Independent Evaluation & Assurance Agents** — "Observe all tiers, assess performance, detect failures and propose improvements"

Key architectural choice: "agents should not be allowed to grade their own work as the sole evidence of performance. Evaluators should use objective system records, independent checks, human review samples and downstream outcomes."

## 6. Part V — Continuous Agent Performance Intelligence

### 7. The defining feature: every agent is continuously evaluated
- Proprietary subsystem: **"Samrudhi Agent Performance Intelligence — SAPI"** — "make agent performance transparent, measurable and continuously improvable."

### Agent Performance Scorecard (proposed default weights)
| Dimension | Weight | Focus |
|---|---|---|
| Output quality | 30% | Accuracy, completeness, brand alignment |
| Efficiency | 25% | Time, cost and resource consumption |
| Reliability | 20% | Completion, errors and recovery |
| Business contribution | 15% | Acceptance, downstream results |
| Feedback & adaptability | 10% | Correction response and sustained improvement |

- "Proposed default weights. Domain-specific weights should differ for creative, analytical, executive and compliance agents."
- **Scoring methodology:** each dimension scored 0–100; `APS = Σ w_i S_i` (i = 1..5).
- "the weighted score must never override critical safety gates. For example, an agent producing unauthorised medical claims or accessing another client's data must fail the relevant control regardless of its overall score."

### Performance monitoring frequencies
| Frequency | Evaluation activity | Response |
|---|---|---|
| Every execution | Input validity, output schema, tool errors, policy violations, cost and latency | Accept, retry, block or escalate |
| Daily | Task completion, exceptions, costs, QA trends | Operational corrections |
| Weekly | Agent scorecards, workflow bottlenecks, human feedback | Improvement backlog |
| Monthly | Benchmark tests, prompt/model comparisons, business outcomes | Controlled version upgrades |
| Quarterly | Agent portfolio review, redundancy, ROI and architecture | Retire, redesign or expand agents |

- "Continuous monitoring means collecting execution telemetry on every run, with evaluations triggered by defined events. It does not require every agent to remain running 24 hours a day."

### 8. Structured feedback architecture
Four feedback sources:
- **Human Feedback** — Approval, corrections, client satisfaction, reviewer notes
- **Independent Agent QA** — Rubric scoring, factual checks, policy checks
- **System Telemetry** — Latency, retries, tokens, failures, tool costs
- **Business Outcomes** — Rework, campaign results, client acceptance, SLAs

- **Unified Feedback Ledger:** "Agent ID · Run ID · Client · Evaluator · Score · Evidence · Root cause"
- **Agent Improvement Pipeline:** "Diagnose → Propose → Test → Approve → Deploy → Monitor"

- "This structure creates a reusable operational dataset instead of losing feedback inside emails and chat conversations."

### 9. Continuous improvement without uncontrolled self-modification
- "Agents should not independently rewrite their own production instructions, expand permissions or deploy untested changes."
- Improvement lifecycle: **Observe** (capture failures, scores, costs, reviewer corrections) → **Diagnose** (poor context, prompting, model capability, tooling, process design or human ambiguity) → **Propose** (documented improvement request with expected impact) → **Test** (against a fixed evaluation dataset and recent representative cases) → **Approve** (human approval for material changes; low-risk changes may follow a preapproved release policy) → **Deploy** (limited percentage of workflows) → **Monitor** (compare quality, cost, latency, failures; automatically roll back on defined breaches).
- "This gives us continuous improvement while preserving reliability and auditability."
